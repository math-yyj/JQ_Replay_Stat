## 第 5 轮

### 用户

你先确定一下，代码解析逻辑里，有没有涉及到"判断哪一家是复盘主视角"的操作？

### 助手

确认结果：**有"主视角"字段的解析，但没有任何逻辑依赖它做判断或变换**。具体情况：

**1. 主视角字段是解析了的**

文件头 `0x0F` 字节就是复盘主视角玩家的颜色，C++ 原工程（block.h L22）和 Python 版（block.py L46）都解析为 `self_color`，并在 game.py L50 存入 `Game._self_color`。

**2. 但它是"只存不用"的死变量**

全局搜索确认：`_self_color` 被赋值后，再无任何代码读取它——C++ 原工程如此，Python 移植版忠实保留了这一点。事件推演、棋盘坐标、布阵解析全都不参考主视角。

**3. 为什么逻辑上可以不依赖主视角**

- 布阵坐标：每个 `JGSPlayerInfoBlock` 里的 6×5 布阵，本来就是该玩家自己视角的布局（row 5 是自家大本营排），文件格式本身与主视角无关。转全局坐标时依据的是每个玩家自己的 `player_color`（黄不转、紫转90°、绿转180°、蓝转270°），全局坐标系固定以黄方在下，与主视角无关。
- 事件坐标：事件块里的起止位置直接就是全局坐标，判断"谁在动"用的是 `_which_player()`（按位置反查棋子归属），也不需要主视角。
- 布阵统计：`LayoutStats` 直接统计各玩家自己视角的 6×5 原始布局，天然对齐（所有人的 row 5 都是自家大本营排），同样不涉及主视角。

**结论**：如果你后续想做"以主视角为基准"的功能（例如把棋盘旋转到主视角在下方显示、或只统计主视角玩家的布阵），`self_color` 字段已经解析好、随取随用，但目前它没有参与任何计算。需要我加个 `Game.self_color` 的公开访问接口，或在统计中支持"仅统计主视角玩家"的选项吗？
